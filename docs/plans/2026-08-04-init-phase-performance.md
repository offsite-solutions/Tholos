# Init phase performance — measurement and fix

**Date:** 2026-08-04
**Status:** Implemented (`perf/instantiate-children-index`)
**Scope:** Backend (`TholosApplication::instantiateComponent`, `loadDefinitionFile`). No template,
JS or Builder changes; no config keys added.

## 1. The complaint

Requests felt slow before anything was rendered, and AJAX partials worst of all: the framework
loads and instantiates the whole action's component tree even when the response is a single grid.

## 2. How it was measured

The debug log's `Tholos_App_InitTime` and the phase markers give the init duration, **but only at
`error,debug` log level**. At `trace` level the logger itself dominates: the `initComponents`
phase, known to take 6 ms, is reported as 6 175 ms across 1 616 log lines. Any timing conclusion
drawn from a trace-level log is wrong by two to three orders of magnitude.

For the breakdown, `TholosApplication` was temporarily instrumented with `hrtime()` probes behind
a `Tholos.ProfileInit` config switch (branch `perf/init-probes`, never released). The probes
measure **exclusive** time: each `instantiateComponent()` frame reports its total to the caller,
so nested calls are subtracted and the buckets sum to the whole.

Environment: local Docker (`app-greengo-bo`), greengo backoffice, `/SAL_CONTRACT_RENTALS/detail/`
— 912 components, 2 537 definitions, 7 `.tcd` files.

## 3. What the profile showed

Warm run, init 727.7 ms:

| bucket | ms | % |
|---|---|---|
| **child scan (revisit)** | **436.1** | **59.9%** |
| `_tholos.init` include | 100.4 | 13.8% |
| unattributed | 87.1 | 12.0% |
| **child scan (create)** | **46.9** | **6.4%** |
| `class_exists` | 28.9 | 4.0% |
| route `.tcd` require | 13.1 | 1.8% |
| `json_decode` (properties + events) | 8.3 | 1.1% |
| constructor (`new $class`) | 5.9 | 0.8% |

```
instantiateComponent calls: 13 658    components: 912    definitions: 2 537
child scan iterations: 13 887 554
```

Two findings decided everything that followed:

1. **The child scans were two thirds of the init phase.** `instantiateComponent()` found a
   component's children by scanning the entire `componentDefinitions` array — on *every* call.
   The array holds every definition loaded so far (2 537 here), the same component is revisited
   many times through `COMPONENT` references (13 658 calls for 912 components), and the
   already-instantiated branch rescans without even logging. Cost grows as
   *definitions × visits*, so the more `.tcd` files a route pulls in, the more expensive every
   further component becomes.
2. **Building the objects is free.** Constructor plus JSON decoding is 14 ms — 2%. Any scheme
   that precomputes component data at build time (bundles with pre-decoded properties, per-entry
   caches) would optimise the one part that costs nothing.

## 4. The change

**`definitionChildIds()`** — a lazily built `pid => children` index over `componentDefinitions`,
dropped in `loadDefinitionFile()` whenever new definitions arrive. It returns a snapshot, which
preserves the previous `foreach` semantics: definitions loaded by a nested `instantiateComponent()`
call are not picked up by the loop already running.

**`resolvedComponentClasses`** — the type hierarchy resolves to the same PHP class for every
component of a type, so it is resolved once per type instead of once per component. 46 of the 84
component types have no PHP class of their own (`TMenuItem` alone accounts for 462 of the 828
misses on this page), and every miss cost an autoloader filesystem lookup.

## 5. Result

Same page, same log level:

| | before | after | |
|---|---|---|---|
| cascade (`TAction` instantiation) | 502 ms | **44 ms** | 11.4× |
| init total, full page | 620 ms | **148 ms** | 4.2× |
| init total, AJAX partial | 725 / 633 ms | ~195 ms | 3.5× |
| whole request, full page | 1 672 ms | 1 292 ms | |

What remains of the 148 ms: `_tholos.init` include 68.5, cascade 44, `TRoleManager` 16.5
(DB session), `TRoute` 12.7, rest 6.8.

## 6. Rejected alternatives

- **Per-entry-point bundles generated by the Builder** (whole cascade in one file, properties
  pre-decoded as PHP arrays). Rejected: it targets the 2% (§3.2), while multiplying build output
  and adding a staleness failure mode.
- **Slicing `_tholos.init` per route at build time.** Real but modest (68.5 ms of the remaining
  148 ms); dropped as not worth the Builder change and the fallback machinery a partial index
  needs to avoid silent misses.
- **File cache of the Optimized auto-open scope ids** (`Tholos.ScopeIDCache`). Rejected after
  measuring the thing it would cache at 0.07–0.12 ms per request — less than the `stat` + `include`
  needed to read the cache.

## 7. Risk

Low, with one caveat about coverage.

**Why the mechanism is safe:** `pid` is a quoted string in every definition (1 141 occurrences in
the sampled files, plus a single `NULL` on the application root), so the index lookup is
equivalent to both comparisons it replaces — the strict `===` of the create branch and the
`(string)` cast of the revisit branch. The index is built by walking `componentDefinitions` in
insertion order, so children keep their definition order. `componentDefinitions` is only ever
extended by `loadDefinitionFile()` and by the two includes in `init()` that run before any
instantiation, so the single invalidation point covers every mutation.

**Why a mistake would be obvious:** a wrong child list means missing, duplicated or misordered
components — a visibly broken page, not a silent data gap. This is the opposite of the
`Optimized` auto-open failures fixed earlier the same day, which showed up only as blank regions.

**Verification:** 61 requests on the local Docker greengo backoffice after the change went live,
covering `SAL_CONTRACT_RENTALS` (18), `PUB_PARTNERS` and eight of its tab routes (26),
`SAL_RENTALS`, `DISPO_DM`, `VEHICLE_INFO`, plus a PDF route — full pages, AJAX partials and
grid partials, confirmed visually and reported as noticeably faster.

Both error logs are clean for that window. The only entries are environmental: four
`Service is not available` (`TExternalDataProvider.php:264` — an external HTTP endpoint
unreachable) and Oracle connection loss over the VPN (`ORA-03113`, `ORA-03114`). No PHP warning
or error originates in Tholos code.

> **Log timezone trap.** The Tholos debug log is written in **UTC**, while the Apache and
> application error logs use **Europe/Budapest**. Correlating them without the two-hour offset
> attributes errors to the wrong code version — a `Trying to access array offset on int` warning
> in `TholosApplication.php` looked like a regression until the offset and the line numbers were
> checked. It came from `getActionId()`'s `array_search(...)['c']` (the `// TODO-BAXi` line), on
> the *previous* revision, when no matching action exists for the URL. Pre-existing and unrelated.

**What is still not covered:** API endpoints, `TDataProxy` paths, workflow pages, the Builder
application, and the other applications on this framework (duvenbeck, ldu, the partner portals)
— a Tholos release reaches all of them, though only the greengo backoffice is upgrading now.

## 8. Reproducing the measurement

`git checkout perf/init-probes`, add `Tholos.ProfileInit=true` to the application config, load a
page at `error,debug` log level, and read the `INIT PROFILE` block from the debug log. In the
local Docker setup `vendor/offsite-solutions/tholos` is a symlink to the working copy, so a branch
switch is live without a deploy.
